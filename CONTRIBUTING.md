# Contributing

Thanks for interest in improving these notes.

## Scope

- Clarifications, typo fixes, and alternative design sections are welcome
- Keep tone technical and specific (numbers, failure modes, trade-offs)
- Prefer Mermaid diagrams embedded in markdown over binary image assets
- Do not add proprietary code, scraped internal docs, or false credential claims

## Process

1. Open an issue describing the gap or alternative approach
2. Fork and branch from `main`
3. Keep PRs focused (one note or one cross-cutting fix)
4. Link related discussion in the PR body

## Style

- Use clear headings: Requirements → Design → Deep dive → Trade-offs
- Call out what you’d ship first
- Cite public references when you lean on a well-known pattern (e.g., token bucket)
